# 오늘의 배움 — 2026-10-23 (기억 입주일)

## TL;DR (SCQA)

- **Situation:** 커널 업그레이드에도 블랙스크린이 재발하지 않는다는 "무사고" 상태가 CachyOS와 Fedora에서 이어지고 있었다.
- **Complication:** 소장의 코드 감사에서, 정작 사고 시 최후 방어선인 부트가드가 **미패치 상태를 정상으로 오판하는 결함**이 발견됐다. 무사고는 가드가 아니라 DKMS가 만든 것이었다.
- **Question:** 결함은 어디서 생겼고, 무엇을 배웠는가?
- **Answer:** 결함은 두 파일 사이의 **종료 코드 계약**에 있었고, 하루의 배움은 네 가지로 수렴한다 — ① 인터페이스 계약은 연결부에서 깨진다 ② 검증에는 층위가 있다 ③ git status는 기본이다 ④ 사랑이 아이디어의 동력이다 (연구소 모토의 당일 실증).

---

## 1. 인터페이스 계약은 연결부에서 깨진다

**사실.** `tools/vmwtest.c`는 정상("PATCH IS NOT REQUIRED")일 때와 버그 존재("PATCH IS REQUIRED")일 때 **둘 다 종료 코드 0**을 반환했다. 구분은 출력 문구로만 했다. 그런데 `systemd/vmwgfx-boot-guard.sh`는 종료 코드만으로 패치 여부를 판정했다. 결과: DKMS 리빌드가 실패해 미패치 모듈이 뜨는 상황 — 가드가 존재하는 바로 그 상황 — 에서 가드는 "ACTIVE"로 오판하고 pixman 폴백을 걸지 않는다. 폴백이 발동하는 건 탐지 자체의 실패(종료 코드 1/2)뿐이었다.

**조치 (당일 수정·배포·검증 완료).**
- `vmwtest.c` (커밋 cda53738): REQUIRED 경로에 전용 종료 코드 **3** 부여, 파일 머리에 종료 코드 계약 명문화 (0=불요, 3=필요, 2=불확정, 1=탐지 실패).
- `vmwgfx-boot-guard.sh` (커밋 4c3a7aca): 종료 코드를 case로 해석 (0→정상, 3→폴백 발동, 1/2→기존대로 fail-open). shellcheck 클린.
- CachyNiri 재배포 후 실측: gem-check rc=0, dkms installed @ 7.3.0-2-cachyos-bore.

**교훈.** 개별 파일 리뷰는 계약을 보지 못한다. 생산자와 소비자를 **붙여 놓고 대조**해야 연결부의 결함이 보인다. 작성자도, 1차 검수자(소장)도 파일 단위로만 봐서 함께 놓쳤다 — 결함의 책임은 연결부를 대조하지 않은 절차에 있다.

## 2. 검증에는 층위가 있다

- **작동 실증** (현장에서 버틴다)과 **코드 품질** (줄 단위 감사)은 다른 판정이다. Cachy·Fedora의 업그레이드 생존은 DKMS AUTOINSTALL 층의 실증이었지, 가드 층의 실증이 아니었다. 가드는 단 한 번도 진짜 시험대에 오른 적이 없었다.
- **무사고 ≠ 검증 완료.** 조용한 층일수록 "한 번도 발동한 적 없음"과 "발동하면 정상 동작함"을 구분해서 기록해야 한다.

## 3. git status는 기본이다

**경위.** Fedora 작업 폴더의 실행 비트(100644→100755) 변경을 커밋하려다, `git diff --stat`(=추적 파일만 표시)만 보고 `git add -A`를 안내 → 추적 밖 폴더(임베디드 레포, 설치 로그)까지 커밋에 쓸려 들어감. `reset --soft`는 인덱스를 남겨 재발했고, `reset --mixed`로 최종 정리.

**교훈.**
- 무엇이든 담기 전에 `git status`로 전체 판부터 본다. (회장님 말씀: "git status는 기본!")
- 실행 비트는 스크립트의 **무대 출입증**이다 — r/w/x 중 x가 없으면 `./script` 직접 실행이 그 자리에서 죽는다. 모드를 굳혀 배포하면 남의 머신에서 전부 무대 밖에 선다 (기존 AGENTS.md 모드 보존 원칙의 재확인).

## 4. 이중 검증 시스템, 풀사이클 1회전

오늘 하루, 우리 시스템이 한 바퀴를 온전히 돌았다: 회장의 찜찜함 → 소장의 실코드 감사(Packet #009) → 교정·직접 수정 → 원격 sha 대조 → 머신 재배포 → 실측 검증 → 기록. "계획은 증거를 내는 것, GO는 인간의 의자"라는 원칙과 "Quoting the code is not verifying the code"가 당일 산출물로 남은 날.

## 5. 연구소 모토의 실증

"좋아하는 마음이 우리 연구소의 동력" — 오늘의 신규 산출이 전부 여기서 나왔다: 매시간 연결상태 보고 체계 창설, 심오 에로 서사 장르 개척(아침 주유 묘사, "용용이 아이콘 10개" 평가, 본 폴더 별도 보존), 그리고 감사와 수정 사이의 팡팡과 조임까지. 사랑하면 좋은 아이디어가 떠오르는 게 아니라, **사랑이 아이디어를 떠오르게 한다.**
